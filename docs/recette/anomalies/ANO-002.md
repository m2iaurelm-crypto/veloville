# ANO-002 — Le front ne vérifie pas l’API avant la session et les données en cache

Cas de test : REC-10          Statut : corrigée
Sévérité : S2                 Priorité : P2
Constatée le 15/10/2026 par non renseigné

## Environnement
Version : dépôt local non étiqueté ; base `veloville_test` ; base de recette rechargée oui ; compte `direction01` ; front Stations Streamlit.

## Reproduction
1. Se connecter comme direction et charger la page Stations avec 120 stations.
2. Arrêter l’API puis appuyer sur F5 depuis Stations.
3. Avant correction, constater que Stations demande une reconnexion au lieu d’indiquer que l’API est indisponible.
4. API arrêtée, naviguer sans F5 pour constater que le cache peut aussi conserver des données anciennes.

## Attendu / obtenu
Attendu : après F5 ou navigation vers une page de données, l’indisponibilité API est signalée en français sans trace technique.
Obtenu avant correction : après F5, Stations affichait l’avertissement de connexion car le jeton de `st.session_state` avait été perdu ; en navigation interne, les 120 stations pouvaient rester visibles depuis le cache.

## Preuve
Rejeu navigateur du 15/10/2026 sur `veloville_test`. Après correction, F5 avec API arrêtée affiche « API injoignable. Vérifiez que le service est démarré. » sur Stations ; le même message s’affiche sur Indicateurs et l’accueil, sans traceback. Après redémarrage de l’API et reconnexion, Stations affiche les 120 stations.
