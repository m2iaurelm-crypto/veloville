# ANO-001 — REC-04 utilise un mot de passe trop court

Cas de test : REC-04          Statut : ouverte
Sévérité : S3                 Priorité : P3
Constatée le 15/10/2026 par non renseigné

## Environnement
Version : dépôt local non étiqueté ; base `veloville_test` ; base de recette rechargée oui ; compte `exploitant01` ; route `POST /auth/login`.

## Reproduction
1. Utiliser le compte de recette `exploitant01`.
2. Envoyer le mot de passe erroné `mauvais`, comme dans REC-04.
3. Comparer avec l’appel utilisant l’utilisateur inconnu `inconnu`.

## Attendu / obtenu
Attendu : les deux appels retournent 401 avec `{"detail": "Identifiants invalides"}`.
Obtenu : `mauvais` retourne 422 avec une erreur de validation indiquant un minimum de 8 caractères ; l’utilisateur inconnu retourne 401.

## Preuve
Rejeu API du 15/10/2026. Contrôle complémentaire : avec le mot de passe erroné `mauvais123` (longueur conforme), les deux appels retournent 401 avec le même message.

## Correction
Commit : à renseigner  Test de non-régression : rejouer REC-04 après remplacement de la donnée par un mot de passe erroné d’au moins 8 caractères.
